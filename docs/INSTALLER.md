# Подготовка установки Minecraft

SC-09 в работе. Реализованы downloader, очередь, resolver 1.8.9, распаковка natives и подготовка базовых файлов через окно лаунчера. Legacy Fabric/Space, замена Log4j, Microsoft-вход и запуск остаются отдельными этапами. Это ещё не полная установка Space Client.

## Готовая часть

`apps/launcher/src/main/downloads.ts` получает только URL, ожидаемые размер/SHA-1 и относительный путь, выбранные main-процессом. Этот API не выставлен в preload: renderer не может передать произвольный URL или путь.

- Только HTTPS и фиксированные Mojang/Minecraft CDN; credentials, query, fragment и нестандартный порт отклоняются. Redirect запрещён. Для object/resource URL хеш в пути должен совпасть с ожидаемым.
- Путь внутри выделенной папки; запрещены traversal, абсолютные пути, обратные слеши, Windows device filenames и ссылки/junction в проверяемых каталогах. Это проверка изоляции приложения, не защита от произвольного процесса того же владельца, который одновременно меняет файловую систему.
- Предельный размер отдельного артефакта 512 МиБ. Ответ ограничен ожидаемым размером, Content-Length/Content-Range проверяются, timeout запроса 30 с.
- Загрузка в `.part`; после проверки размера и SHA-1 — rename. Старый файл не заменяется повреждённым. Корректный готовый файл повторно используется после проверки хеша.
- Отмена и сетевой обрыв сохраняют часть файла; повторный вызов запрашивает Range. Неверный диапазон не дописывается; если сервер игнорирует Range и отдаёт 200, файл начинается заново.
- Отдельный lock на destination не допускает двух одновременных записей в один файл. SHA-1 берётся из официальных Mojang metadata и проверяет совпадение содержимого; это не цифровая подпись издателя. Источник metadata должен проверяться отдельно.

## Очередь файлов

`src/main/download-queue.ts` валидирует весь набор до файловых операций: не более 10000 исходных записей и 2 ГиБ уникальных файлов, дедупликация по Windows path, запрет конфликтующих hashes, file/directory collisions и пересечения с временными `.part`. Проверка вложенных путей не перебирает весь список для каждой записи.

По умолчанию три worker, допустимо 1–4. Для HTTP 429/5xx, сетевого обрыва, timeout и повреждённого содержимого — максимум два повтора (три попытки) с задержками 250/500 мс; постоянные ошибки и файловые ошибки не повторяются. При невосстановимой ошибке или отмене общий AbortSignal останавливает остальные worker и ожидается их завершение. Сохранённые корректные файлы и .part остаются для следующего вызова.

Прогресс разделяет receivedBytes (текущие частичные данные, могут уменьшиться после отклонения повреждённого файла) и verifiedBytes (только завершённые файлы). `completed` выдаётся только после успешной проверки всего набора; failed/cancelled не маскируются под завершение. Progress callback наблюдает за очередью, его исключение не бросает работающие worker; отмена выполняется AbortSignal. Очередь подключена к main-only lifecycle и UI.

## План 1.8.9

`prepareVersionPlan` скачивает только закреплённые version JSON и asset index: фиксированные URL/размер/SHA-1 заданы в исходниках. Хеш проверяется до JSON.parse. Чистая функция `buildVersionPlan` составляет список файлов, classpath и перечень native-архивов; она не запускает процессы и не использует `minecraftArguments` из удалённого JSON.

- Поддерживается только release 1.8.9 / Windows x64 / assets 1.8. OS rules применяются по последнему совпадению; неизвестные conditions, features, OS version/arch отклоняются. Это не универсальный resolver всех версий.
- Maven path и URL должны соответствовать координатам библиотеки. macOS-only библиотеки исключаются; `${arch}` для Windows natives заменяется на 64. Разрешено только исключение META-INF/ при будущей распаковке.
- Assets записываются исключительно по hash в `assets/objects/<prefix>/<hash>`; логические имена не превращаются в файловые пути. Одинаковые объекты дедуплицируются; несовпадение размера одинакового hash отклоняется. virtual/map_to_resources пока не поддерживаются.
- Исходные metadata содержат Log4j 2.0-beta9. Все `org.apache.logging.log4j` исключаются из файлов и classpath; план остаётся `launchReady: false`. До запуска нужна закреплённая совместимая замена. Известная уязвимость этой версии подтверждается [Apache security advisories](https://logging.apache.org/security.html); настройка legacy XML не считается заменой обновления библиотек.
- Возвращаются явные blockers: Log4j override, Legacy Fabric/Space, установка/распаковка, авторизация/владение/runtime. Готовый список файлов не означает готовность игры.

Реальный preview, скачивающий только 96 738 байт двух JSON:

```powershell
node apps/launcher/scripts/preview-plan.mjs
```

Проверено 23.10.2026: 758 уникальных файлов, 734 логические записи assets (часть hashes повторяется), 30 classpath entries без legacy Log4j, четыре Windows native-архива, 145 084 967 байт запланированных файлов. Полный plan.json хранится в игнорируемой `.reports/launcher-plan-smoke`; [краткий результат](qa/launcher-plan-2026-10-23.json) сохранён в репозитории. Архивы и игра этим preview не загружаются.

## Распаковка natives

`extractNatives` повторно проверяет SHA-1/размер локальных архивов без сети, затем распаковывает их в новую уникальную генерацию `natives/run-*`. Старые генерации не заменяются. При ошибке/отмене удаляется только созданная этим вызовом staging-папка, после проверки абсолютного пути очистки. Готовый путь возвращается только после успешной обработки всех записей; DLL не загружаются.

- Зафиксированы `yauzl 3.4.0` и `@types/yauzl 3.4.0`; последовательное чтение lazy entries, strictFileNames, проверка размеров. Дополнительно проверяется CRC32 каждой распакованной записи и вычисляется SHA-256 результата. CRC не является доказательством источника; источник архива связан с metadata SHA-1 и HTTPS.
- Максимум восемь архивов по 32 МиБ, 2048 записей суммарно, 32 МиБ на запись и 128 МиБ объявленного распакованного содержимого, включая исключённые записи. Фактический поток не может превысить размер записи.
- Запрещены traversal/absolute/Windows device paths, backslash, symlink/специальный Unix type, reparse attributes, encrypted entries, неподдерживаемое сжатие, case collisions и file/directory collisions. META-INF/ исключается после проверки имени и свойств.
- Отмена проверяется перед операциями и при чтении, активный поток уничтожается. Offline-проверены предварительная отмена, rollback повреждённого архива и сохранение старой генерации; UI-отмена распаковки ещё не проверена.

Реальная проверка только официальных native-архивов:

```powershell
node apps/launcher/scripts/smoke-natives.mjs
```

23.10.2026 скачаны четыре архива (8 806 644 байта), проверены hashes и распакованы 14 DLL (25 323 600 байт) с CRC/size checks. Windows x64 классификаторы Twitch выбраны корректно; общие LWJGL/JInput архивы содержат обе архитектуры. [Список файлов и SHA-256](qa/launcher-natives-2026-10-23.json). Данные находятся в игнорируемой `.reports/launcher-native-smoke`; бинарники не коммитятся. Успешная распаковка не подтверждает загрузку DLL или запуск игры.

## Подготовка через окно

`InstallationService` использует фиксированный `instances/<profile-id>/minecraft`, полученный из ProfileStore. Renderer передаёт только известный ID профиля. Узкие IPC: get/start/cancel, проверка sender/mainFrame/URL сохранена; состояние опрашивается через preload раз в 650 мс. Одновременно допускается одна подготовка во всём приложении, включая асинхронное создание каталога. Настройки других профилей не блокируются; при попытке начать вторую подготовку main возвращает понятную ошибку.

Этапы: planning → downloading → extracting → prepared; отдельно cancelling/cancelled/error. После metadata проверяется свободное место с консервативным резервом 160 МиБ сверх полного размера плана. При отмене ожидается завершение worker/распаковки. Закрытие приложения вызывает shutdown перед quit. Ошибка не заменяет прошлый успешный receipt. `base-installation.json` записывается через уникальный temp + rename только после всех этапов, содержит `kind: minecraft-base-only`, `launchReady: false` и blockers. Receipt не является разрешением запуска; после перезапуска UI честно показывает, что файлы ещё не проверялись в этом сеансе. Повторная подготовка заново проверяет hashes и использует кеш.

### Реальная приёмка

В изолированном desktop-профиле через UI начата подготовка; отмена сработала на 88/758 проверенных файлах (33,8 МиБ). Успешный receipt после отмены отсутствовал. Повторный запуск использовал уже проверенные файлы; работа завершилась на 758/758, 145 084 967 байтах и 14 DLL. В момент проверенной отмены неполных `.part` не осталось: сохранение частичных байтов подтверждено отдельными offline/Range-тестами, а не этим UI-сценарием.

Затем у одного тестового asset размером 73 байта изменён первый байт с резервной копией оригинала. Верификатор отклонил его hash. Кнопка «Проверить и восстановить» вернула правильное содержимое; последующий аудит проверил SHA-1 всего плана и SHA-256 natives относительно локального receipt. [Полный итог проверки](qa/launcher-base-2026-10-23.json), [контроль повреждения](qa/launcher-repair-fixture-2026-10-23.json). Авторизация, Java/game process и загрузка DLL этим сценарием не проверялись.

Команды только для disposable-профиля этой задачи, не для личной установки:

```powershell
# Проверить подготовленный через UI профиль default.
node apps/launcher/scripts/audit-base-installation.mjs
# НАМЕРЕННО повреждает один небольшой скачанный asset внутри .reports/launcher-desktop.
node apps/launcher/scripts/prepare-repair-fixture.mjs
# Затем в лаунчере: «Проверить и восстановить», после завершения повторить audit.
```

## Дальнейшая очередь

1. Закрепить совместимую замену Log4j и Legacy Fabric/Space manifest; перед запуском проверить весь classpath в реальном runtime.
2. Дополнить UI проверкой места/ошибок на реальном недостатке диска и отменой при закрытии приложения; эти пути пока проверены модельно.
3. Проверять native generation перед использованием; предусмотреть очистку старых и брошенных генераций с учётом работающих процессов. Сейчас они не запускаются и автоматически не удаляются.
4. Legacy Fabric loader и собственный remapped Space jar связать с контролируемым манифестом и проверенными хешами. Mojang-файлы не переупаковывать в репозиторий.
5. Перед запуском — проверка готовности всех файлов, Java, лицензии/профиля и актуальной авторизации; один процесс на профиль.

## Источники

- [Официальный version manifest Mojang](https://piston-meta.mojang.com/mc/game/version_manifest_v2.json): запись 1.8.9 проверена 23.10.2026.
- [Закреплённые metadata 1.8.9](https://piston-meta.mojang.com/v1/packages/d546f1707a3f2b7d034eece5ea2e311eda875787/1.8.9.json): client URL/size/hash, asset index и 37 library entries. Старые launcher.mojang.com/launchermeta.mojang.com остаются в этих metadata; нельзя предполагать только новые piston-hosts.
- [Документация installer проекта XMCL](https://xmcl.app/en/core/installer): независимый первичный источник о его собственных CDN defaults, включая resources.download.minecraft.net. Код XMCL не копировался.
- [yauzl API](https://github.com/thejoshwolfe/yauzl): lazy entries, validateEntrySizes, strictFileNames и потоковое чтение. Используется как библиотека ZIP parsing; политика каталогов и лимиты задаются нашим кодом.
