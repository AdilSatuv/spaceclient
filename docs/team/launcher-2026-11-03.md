## Поведение после правок

- Согласованный с ведущим ID: `dev-<первые 12 hex gameSourceTree>`. Он обозначает исходники; точные байты различаются полным SHA-256 и размером. Для проверенного исходного bundle ID — `dev-1172b80ffdcb`.
- `InstallationStatus.bundledBuild` показывает compile-time pin этой версии лаунчера даже до подготовки. `spaceVersion` оставлен совместимым полем, но больше не служит доказательством проверки в UI.
- `LaunchPlan.verifiedBuild` берётся из результата inspection установленного JAR. План возвращается только после существующих проверок Java, pinned metadata/всех файлов, JAR, единственного мода и natives. `LaunchStatus.verifiedBuild` публикуется после успешного полного preflight, содержит identity и checkedAt.
- В idle/checking и при неуспешном preflight verifiedBuild=null. Новая попытка сбрасывает прежний результат до первого await; другой профиль его не наследует. Ошибка процесса после успешного preflight сохраняет исторический результат проверки, помеченный «Последняя проверка перед запуском». Эти сведения хранятся только в памяти текущего сеанса; receipt и старые настройки не выдают себя за проверенные байты.
- В карточке файлов отдельно показаны «Сборка в лаунчере» и состояние последней проверки установленного Space. Native details/summary открывается клавиатурой, полные tree/SHA-256/размер/версии можно выделить. После preflight доступны два набора полных значений и время. Совпадение определяется по tree, digest и размеру, а не по short ID или 0.1.0.
- Подготовка помечена «Подготовлены», без заявления о preflight. Без bundled Space показано отсутствие игровой сборки и объяснено, что доступны только базовые файлы Minecraft.
- Начальная инструкция объясняет подготовку. Ошибки JAR/natives направляют в карточку «Файлы игры»; ошибки подготовки объявляются через alert. Есть «Повторить подготовку», «Повторить запуск» и отдельный повтор чтения статуса, который не начинает установку.
