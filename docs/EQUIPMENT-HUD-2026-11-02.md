# Armor HUD и карточки эффектов · 2 ноября 2026

В **Armor → Content → Display style → Icons** добавлен ряд шлем/нагрудник/поножи/ботинки и выбранный предмет в руке. Используется собственная карточная геометрия и стандартный игровой рендерер предметов, включая зачарование. Durability выбирает проценты или остаток в единицах; Held item скрывает последний слот. Полоски отражают реальную оставшуюся прочность: зелёный/золотой/красный, подпись критического остатка также красная. Пустой слот обозначен буквой и `-`, предмет без расходуемой прочности — `n/a`, некорректные данные — `?`, полоски для таких значений не рисуются. Процент положительного остатка округляется вверх, а ширина ячеек резервируется по максимальному значению, чтобы износ не сдвигал соседей.

В **Potion Effects → Content → Display style → Icons** добавлены карточки с иконкой, названием, уровнем и временем. Можно показывать 1–5 эффектов и отдельно скрывать таймер. Список сортируется по ID; остальные эффекты обозначаются `+N more`. Последние десять секунд выделяются цветом, постоянные эффекты используют `**:**`. Нет эффектов — `Effects: none`, нет игрока — `Effects --`. Длинные названия ограничиваются и сокращаются; управляющие, bidi-format и surrogate символы отфильтрованы. При отсутствии штатной иконки показывается `?`. Ресурсы сторонних клиентов не копировались: значки берутся из существующего игрового атласа, предметы — через API Minecraft.

Цвет/фон/тень, размещение, масштаб и два HUD-профиля поддерживаются для обоих вариантов. Текстовый стиль сохранён по умолчанию и при миграции; общий HUD и отдельные модули автоматически не включаются. Переход на иконки меняет размер, поэтому положение можно поправить через Edit layout. Предпросмотр использует тот же рендерер. Полная высота списка, дополнительная строка `+N` и ряд брони участвуют в bounds/anchor/drag/nudge/fitting редактора.

HUD schema **14**, экспорт **v9**; схемы 1–13 и экспорты v1–v8 поддерживаются. Перед первой записью миграции сохраняется проверенная копия файла. Добавлены реальные fixtures schema13/exportv8 из предыдущего проверенного JAR `96825f9`; они подтверждают сохранение Block Keystrokes, Compact Sprint, старых цветов/размещений и независимость профилей. EquipmentContent хранит новые форматы отдельно внутри содержимого профиля, старые изменения Content их не сбрасывают. Неполные/неизвестные значения отклоняются.

Прошли **167 Java-тестов и 112 тестов лаунчера**, TypeScript, Prettier затронутых файлов лаунчера, сборки, состав и source stamp JAR. Проверены форматирование остатка/долей, неизвестные/пустые значения, сортировка/лимит/таймеры, переполнение, геометрия и перенос предыдущих профилей. [Машинные результаты и хеши](qa/equipment-hud-2026-11-02.json).

В отдельном невидимом QA Minecraft вручную через игровой API заданы повреждённый зачарованный шлем с единицей остатка, нагрудник на половине прочности, пустой слот поножей, целые ботинки, повреждённый зачарованный меч и шесть эффектов. Проверены реальные методы экранов для выбора стиля, единиц, скрытия руки, лимита до пяти и таймеров; полный размер и четыре anchor редактора, независимость профилей, повторное чтение сохранений и пустые состояния. Получены/осмотрены шесть framebuffer-снимков 1280×720, включая мир, Content, редактор и отдельный экран проверки отрисовки. Финальный exitCode=0, ошибок Mixin/текстур не наблюдалось. Это проверка адаптеров/отрисовки на явно заданных QA-данных, не прохождение получения предметов/эффектов в survival. Физический ввод, multiplayer, FPS и полная матрица драйверов/ресурспаков/шейдеров не проверялись.

Игровая проверка выявила изменение alpha blend factors после native item renderer: стандартный `blendFunc` меняет обе GL-пары, но обновляет только RGB-кэш. Теперь за восстановлением через GlStateManager следует принудительное восстановление записанных GL-пар. Снимок состояния до/после Armor и Effects совпадает для lighting/цвета/depth/blend/alpha/culling/texture/matrices; повторные cache-backed вызовы depth/blend не меняют это состояние. Световые атрибуты и текстуры также возвращаются после рендера, чтобы следующие виджеты/экраны не зависели от выбранного предмета.
