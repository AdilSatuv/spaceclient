Статус: реализация первого прототипа. Название утверждено пользователем. Стек сайта по выбору пользователя: Next.js + NestJS, TypeScript. Игровое ядро первого прототипа: Legacy Fabric 1.8.9 (см. ADR-001).

Текущий статус на 24 октября: локальный ник и настоящий запуск SC-25, оформление лаунчера SC-26 и игровая приёмка SC-02/03/04 завершены. Редактор HUD SC-05 прошёл игровую матрицу, профили/миграцию/перезапуск — [HUD-EDITOR.md](HUD-EDITOR.md). FSD-архитектура сайта описана в [WEB-ARCHITECTURE.md](WEB-ARCHITECTURE.md); приёмка меню — [HUD-MODULES.md](HUD-MODULES.md). Сценарий лаунчера по выбору пользователя — локальный ник и одиночная игра: [SC-25](LOCAL-LAUNCH.md). Собственная Space-регистрация — отдельный будущий срез. Microsoft-вход и публикация сайта отложены. Требования Microsoft/владения ниже сохраняются для будущего официального онлайн-сценария. Оставшиеся игровые и веб-проверки сохраняются в трекере, передача между чатами — [CHAT-HANDOFF.md](CHAT-HANDOFF.md).

## Цель и границы

Создать самостоятельный Minecraft Java PvP-клиент с лаунчером и сайтом. Первая целевая платформа — Windows 10/11 x64, первая игровая версия — 1.8.9. Главный сценарий: скачать → установить → войти Microsoft → подготовить профиль → запустить игру → настроить HUD → сохранить профиль.

MVP: запуск лицензионной игры, управление памятью, стабильные настройки, 4 модуля HUD, редактор расположения, диагностика и сайт загрузки. Не входят: магазин, платежи, друзья, голос, облачные профили, античит, собственный сервер, несколько игровых версий, полноценные macOS/Linux-сборки. Косметика — последующая независимая задача.

## Архитектура

```text
Сайт → релизы GitHub / документация
Лаунчер → Microsoft auth → профиль → установка файлов → процесс Java
                                                      ↓
                                Space game mod → модули → HUD editor
```

Предлагаемый monorepo:

```text
apps/website/       сайт и статические материалы
apps/api/           NestJS read-only API контента
apps/launcher/      desktop main/preload/UI
packages/content-contracts/ общий контракт контента Next/Nest
game/              Java-мод и адаптер Minecraft 1.8.9
docs/              исследование, решения, инструкции
scripts/           проверки и сборка
.github/workflows/ CI
```

Лаунчер: первый Windows-прототип на Electron 45.0.0 + React 19.3.1 + TypeScript 5.9.3, сборка esbuild 0.28.2. Решение и ограничения — в [LAUNCHER.md](LAUNCHER.md). Размер и RAM готового пакета ещё требуют измерения. Сайт: Next.js App Router; backend: NestJS с API статуса и релизов, без аккаунтов и базы на первом этапе. Слои HTTP/application/repository и общий пакет контрактов реализованы; схема — WEB-ARCHITECTURE.md. Game core: Java + Legacy Fabric. Современные Fabric/Sodium не считать готовыми зависимостями 1.8.9.

## Требования и приёмка

| ID | Требование | Как принимаем |
|---|---|---|
| L01 | Изолированные launch-профили | Два профиля не меняют файлы и настройки друг друга |

| L03 | Установка версии | По манифесту загружаются client, libraries, assets, natives; проверяются размеры/хеши |
| L04 | Восстановление | Обрыв загрузки и повреждённый файл исправляются без полной переустановки |
| L05 | Вход | Внешний браузер, отмена/истечение обрабатываются; токены не попадают в логи |
| L06 | Владение игрой | Перед онлайн-запуском подтверждены доступ и профиль Minecraft |
| L07 | Управление процессом | Один запуск на профиль, состояние/выход видны, коды аварий сохраняются |
| L08 | Сохранение настроек | После перезапуска значения совпадают; повреждённый JSON не ломает UI |
| G01 | FPS/CPS | FPS берётся из игры; CPS считает реальные нажатия в скользящем окне 1 с |

| G04 | Config | Версия схемы, миграция, отдельное хранение launch/HUD; импорт валидируется |
| S01 | Сайт | Главная, возможности, загрузки, changelog, FAQ/помощь |

## Безопасность и эксплуатация

Из renderer нет прямого доступа к файловой системе или shell. Узкий типизированный IPC с проверкой отправителя и каждого аргумента. Sandbox/context isolation, CSP, запрет произвольной навигации. Java запускается через execFile/spawn с массивом аргументов, без shell. Пути установки ограничены каталогом инстанса; архивы защищены от выхода за него. Не принимать произвольные команды из удалённого манифеста.

Refresh token хранить средствами ОС; идентификатор OAuth public client не является секретом. Для Microsoft/Xbox/Minecraft отдельно подтвердить необходимые регистрации и разрешения до обещания рабочего входа. Продакшен-обновления требуют подписанного канала; обычный SHA-256 проверяет целостность, но не заменяет подпись источника. Логи исключают токены и персональные данные. Профиль игры не переиспользует данные конкурентов.

## Очередность

1. **Исследование:** этот документ, сравнение, список рисков. Готово по публичным источникам; практическое тестирование конкурентов пока не выполнено.
2. **Технический эксперимент:** Forge 1.8.9 против Legacy Fabric; минимальная сборка и запуск dev-клиента, текст на HUD, обработка клавиши, сохранение настройки. Зафиксировать JDK/Gradle/loader и причину выбора. Приёмка: повторяемый запуск и сборка из чистого clone.
3. **Основа проекта:** workspace, закреплённые зависимости, CI, схемы конфигов, бренд и статический сайт со статусом разработки. Лаунчер сохраняет профиль и диагностирует runtime.
4. **Вертикальный сценарий запуска:** регистрация приложения, Microsoft→Xbox→Minecraft, проверка доступа, установка одной версии, запуск Java, логи. Приёмка на чистом Windows-профиле с законным аккаунтом.
5. **Игровой MVP:** FPS/CPS/Keystrokes/Coordinates, каталог модулей, HUD editor, два профиля, миграция и сброс.
6. **Оптимизация:** контролируемый benchmark vanilla / Space без модулей / Space с HUD. Одинаковые мир, разрешение, настройки, маршрут, прогрев; минимум три прогона. Средний FPS, 1% low, frametime, RAM и время запуска. Цель первого прохода — отсутствие заметной регрессии, а не неподтверждённое «2× FPS».
7. **Alpha:** установщик, подпись при доступном сертификате, проверка восстановления, релиз и подключение реальной загрузки на сайте. Публикация сайта — после проверки содержания и мобильной версии.

Сроки не закреплены до результатов эксперимента и проверки авторизации. Главные риски — старый Java toolchain, игровой API-вход, совместимость OpenGL/драйверов и стоимость поддержки runtime. Для каждого риска сначала воспроизводимый эксперимент, затем основной код.

## Первый результат разработки

В ближайшем срезе достаточно: проверяемый Java toolchain, выбранный loader, минимальный настоящий HUD-мод, рабочая локальная страница сайта со статусом и CI. При отсутствии Microsoft-разрешений dev-клиент и тестовый стенд не выдаются за готовый пользовательский лаунчер.
