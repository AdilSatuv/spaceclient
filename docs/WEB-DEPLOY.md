# Размещение Next.js + NestJS

Статус: по решению пользователя от 24 октября сейчас достаточно локального preview. Команда `npm.cmd run preview:web` собирает и запускает Next + Nest на временных loopback-портах; ссылка выводится в терминале. Публичный сайт не размещён, провайдер и домен не выбраны. Дальнейшая инструкция предназначена для будущей публикации, не означает покупку хостинга или включение индексации.

## Что требуется от окружения

- Два управляемых Node.js 24+ процесса с перезапуском и просмотром журналов.
- HTTPS-origin сайта и приватное соединение Next → Nest. Браузер обращается только к Next.
- Одинаковый Git commit для сборки, runtime и rollback; `npm ci` по lockfile.
- Записываемый cache Next Image; исходные изображения поставляются в репозитории.

## Подготовка версии

1. Выбрать проверенный commit из main с зелёным Verify. Проверить оставшиеся пункты WEBSITE-QA.md.
2. Установить Node 24+, выполнить `npm ci` в чистой копии, затем `npm test` и `npm run format:check`.
3. Задать final env **до build**: реальный `SPACE_SITE_URL`, `SPACE_SITE_INDEXABLE=false` для preview; `SPACE_API_URL` — приватный адрес API. Не менять origin только после сборки: у статических страниц metadata уже зафиксирована.
4. Выполнить `npm run build`, `npm run check`, `npm run check:web:states`. Последняя команда поднимает временные localhost-серверы, а не публикует fixture-каталог.
   Сборка API/Next автоматически собирает @space/content-contracts. При упаковке отдельных процессов включить `packages/content-contracts/package.json` и `dist` вместе с workspace-зависимостями; не копировать один `apps/api/dist`. Не запускать из разных commit общий пакет и приложение.
5. Сохранить build/commit и предыдущее рабочее окружение. Не редактировать production каталог вручную ради демонстрации кнопки скачивания.

## Запуск

На одном сервере за TLS reverse proxy API может остаться на `HOST=127.0.0.1`, `PORT=3001`; Next использует `SPACE_API_URL=http://127.0.0.1:3001`. Команды в двух управляемых процессах:

```text
npm run start --workspace @space/api
npm run start --workspace @space/website
```

Если платформа требует bind всех интерфейсов внутри изолированной сети: API получает `HOST=0.0.0.0`, свой `PORT`; Next запускается `npm run start:hosted --workspace @space/website -- --port <PORT>`. API ingress остаётся приватным; public origin и TLS относятся к Next. Конкретные network/service настройки зависят от выбранного хостинга и ещё не применялись.

`.env.example` — пример, не секреты и не автоматическая настройка сервера. Nest не читает `.env` самостоятельно: process env задаётся менеджером процессов/платформой. Next читает свои env-файлы из apps/website; production значения лучше задавать средствами платформы.

## Проверка preview и публикация

1. У API `/v1/health` отвечает `status=ok`. У сайта главная, features, download, updates, help открываются; неизвестная запись — 404.
2. До принятия preview `/robots.txt` запрещает обход, sitemap пуст, canonical не содержит localhost или подставного домена.
3. При остановке API главная/help остаются доступны, каталог показывает ошибку с ручным повтором, а не «релизов нет». После восстановления данные возвращаются.
4. Проверить изображения, mobile menu, фильтры/Back, clipboard fallback и открытие прямых article URL через публичный HTTPS-origin. Выполнить performance-матрицу ТЗ.
5. После окончательной приёмки включить `SPACE_SITE_INDEXABLE=true`, **пересобрать** с тем же final HTTPS-origin и проверить robots, canonical, Open Graph и sitemap в ответах сервера.
6. Настроить наблюдение за процессами/health средствами выбранного хостинга. Автоматизация внешнего мониторинга ещё не создана.

## Rollback

Вернуть предыдущий проверенный build/commit вместе с соответствующими env, перезапустить оба процесса, проверить health, главную и download empty/error. Новые артефакты клиента не появляются из rollback сайта: релизы отдельно проходят проверку контракта и changelog. Для ошибочной сборки использовать `withdrawn=true`, сохранив историю и убрав действие загрузки.

На текущем этапе базы данных и миграций нет. Перед добавлением аккаунтов, магазина или CMS эта инструкция пересматривается.
