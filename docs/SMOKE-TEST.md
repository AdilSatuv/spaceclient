`./scripts/game.ps1 build` проходит: **9 Java-тестов** (4 HudConfig, 5 ClickCounter), failures/errors=0. Покрыты независимые окна L/R, release и удержание, точная граница 1 секунды и затухание без новых событий, меню, движение/колесо/средняя кнопка, переполнение монотонного счётчика времени, round-trip и старый config без cps. Проверки не используют реальные паузы, часы передаются через LongSupplier. CPS — число обработанных нажатий за последнюю секунду, а не число нанесённых ударов или игровых use-action при удержании.

Точки подключения сверены с mapped bytecode 1.8.9 build 604: mouse hook вызывается один раз при чтении vanilla `Mouse.getEventButton`, не забирает событие через `Mouse.next`; F8 обрабатывается в `handleKeyInput`, key-up и repeat игнорируются. Исключение меню/потери фокуса/отсутствия игрока реализовано в адаптере; тесты счётчика сами по себе не подтверждают все эти сценарии внутри Minecraft.

Снимки игрового HUD и выключенного HUD после перезапуска сохранены отдельно в outputs чата. Runtime, мир и config не коммитятся.

## 24 октября: завершение физической приёмки SC-02

В окно 854×480 вернулись для физического ввода. Computer Use не предоставляет длительное удержание; эти результаты подтверждены пользователем в ответах на конкретные сценарии, а не автоматическими снимками.

| Сценарий | Подтверждённый результат |
|---|---|
| Исходные WASD | Поочерёдное удержание даёт [W]/[A]/[S]/[D], отпускание убирает скобки |
| F8, 5 секунд | Одно переключение; отпускание не переключает, следующее отдельное нажатие переключает |
| F8 при выходе из паузы | Зажат в паузе, Back to Game мышью, отпускание: видимость сохраняется; новое нажатие переключает |
| F8 при выходе из HUD menu | Тот же сценарий с меню правого Shift и Done: видимость сохраняется |
| Переназначенные movement bindings | Во временной сессии ↑/←/↓/→ назначены на forward/left/back/right (LWJGL 200/203/208/205). Они дают [W]/[A]/[S]/[D]; отпускание снимает состояние, старые WASD его не включают. Буквы обозначают игровые действия |
| Правый Shift | Новая версия открывает меню и закрывает следующим отдельным нажатием; при удержании 5 секунд открытое меню остаётся открытым, после отпускания новое нажатие закрывает |

Последний сценарий потребовал дополнения: правый Shift теперь не только открывает, но и закрывает меню. В 1.8.9 tick вызывает handleKeyInput до передачи события новому Screen, а Screen.handleKeyboard вызывает его повторно. Простое закрытие в keyPressed закрыло бы только что открытое меню либо привело к повторному открытию. KeyPressGate исключает повторную обработку одного timestamp и repeat events, допускает новый press после release и после пропущенного release при потере фокуса. F8 не изменён. В меню добавлена подсказка `Right Shift / Esc - close`; для Shift+Tab использовать левый Shift.

`scripts/game.ps1 build`: **23 теста** (прежние 19 + 4 KeyPressGate), failures/errors=0. С новым кодом загружен тот же мир, физически проверены стрелки и двусторонний правый Shift. После Save and Quit → Quit Game процесс штатно завершён. Исходный options.txt восстановлен из резервной копии **побайтно**, SHA-256 совпадает: WASD 17/30/31/32, GUI Auto, fullscreen=false, overrideWidth/Height=0. Dev-конфиг после QA: master OFF, FPS ON, Coordinates/Keystrokes/CPS OFF; это тестовое состояние, defaults в коде не менялись.

Все критерии SC-02 подтверждены. SC-03 и полная приёмка меню SC-04 остаются отдельными незавершёнными задачами. Сайт на прежнем localhost-порту оставлен работающим; runtime, мир, настройки и игровые бинарные файлы не коммитятся.
