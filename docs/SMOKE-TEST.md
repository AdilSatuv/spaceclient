- Windows x64, Temurin 21.0.12.1, Legacy Fabric Loader 0.18.3, Space Client 0.1.0.
- `./scripts/game.ps1 build`: успешно, 3 теста HudConfig без ошибок.
- `runClient`: загрузка Mixin, инициализация Space Client, resources atlas и звукового движка подтверждены логом.
- Log4j API/Core закреплены на 2.26.1, dev-конфиг заменён клиентским. Старые CLASS_NOT_FOUND/PatternLayout/invalid level/ServerGuiConsole отсутствуют.
- Осталась ошибка Twitch SDK старого Minecraft. Сценарий Twitch не входит в MVP, но ошибка не считается устранённой.

## Проверка в мире и CPS — 23 октября 2026

Windows x64, то же закреплённое окружение. Открыт существующий Creative singleplayer-мир из игнорируемого `game/run/saves`; пользовательская установка Minecraft не использовалась. Размер клиентской области 854×480, GUI scale по текущим настройкам dev-инстанса. Это функциональная проверка, а не benchmark FPS.

| Сценарий | Фактическое наблюдение |
|---|---|
| HUD в мире | SPACE CLIENT, FPS, XYZ и строка клавиш отображаются; после обновления добавлена CPS |
| XYZ/F3 | HUD `-35.3 / 63.0 / -4.4`, F3 `-35.300 / 63.000000 / -4.396`: совпадают с учётом округления |

| F8 в паузе | Не меняет сохранённое enabled=false |

| Стабильность запуска | Mixin загружен, мир открыт в двух сессиях нового кода, аварии и ошибки Mixin в latest.log не обнаружены. Старая ошибка Twitch остаётся |

`./scripts/game.ps1 build` проходит: **9 Java-тестов** (4 HudConfig, 5 ClickCounter), failures/errors=0. Покрыты независимые окна L/R, release и удержание, точная граница 1 секунды и затухание без новых событий, меню, движение/колесо/средняя кнопка, переполнение монотонного счётчика времени, round-trip и старый config без cps. Проверки не используют реальные паузы, часы передаются через LongSupplier. CPS — число обработанных нажатий за последнюю секунду, а не число нанесённых ударов или игровых use-action при удержании.

Точки подключения сверены с mapped bytecode 1.8.9 build 604: mouse hook вызывается один раз при чтении vanilla `Mouse.getEventButton`, не забирает событие через `Mouse.next`; F8 обрабатывается в `handleKeyInput`, key-up и repeat игнорируются. Исключение меню/потери фокуса/отсутствия игрока реализовано в адаптере; тесты счётчика сами по себе не подтверждают все эти сценарии внутри Minecraft.

Снимки игрового HUD и выключенного HUD после перезапуска сохранены отдельно в outputs чата. Runtime, мир и config не коммитятся.

## 24 октября: продолжение SC-02 и новая клавиша меню

По просьбе пользователя открытие меню перенесено с F9 на правый Shift; F8 по-прежнему переключает общую видимость. `scripts/game.ps1 build` после изменения проходит, 19 тестов без failures/errors. Старые проверки F9 выше относятся к предыдущей версии; новое назначение требует отдельного подтверждения физической клавишей. Одиночный `Shift_R` через Computer Use не дал однозначного подтверждения.

Новый процесс с изменённым кодом запущен в том же мире при overrideWidth=1280 / overrideHeight=720, GUI Auto (масштаб 3, 427×240 GUI units). Заголовок, FPS, XYZ и строка клавиш помещаются в клиентской области. Это пока не завершённая матрица 720p: F1/F3, другие GUI scale и 1080p ещё не проверены в этом срезе.
