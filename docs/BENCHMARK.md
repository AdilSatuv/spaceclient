# Измерения и совместимость — SC-13

24 октября 2026: выполнены девять настоящих локальных captures (по три vanilla / Space HUD OFF / Space HUD ON), анализатор принял все записи. После первого круга был пользовательский перерыв и изменились фоновые приложения, поэтому это разведочная статическая серия. Она не устанавливает точную стоимость HUD или ускорение Space. Отдельный [startup-срез](STARTUP-TIMING.md) теперь содержит preflight/spawn и наблюдаемые верхние границы до главного меню Space. SC-13 остаётся открытой: точное время до готового игрового кадра не измерено, официальный baseline/запуск зависит от SC-10.

## Инструмент

Внешний PresentMon 2.3.1 x64 измеряет интервалы Present для одинакового процесса Java во всех вариантах. Он не добавляет измерительный код в HUD и не изменяет игровой JAR. Версия закреплена, SHA-256 официального executable: `364e5d98d4d134bd54dd25c22ed2ca2f4883f8bc3ed6502bee0c151e3436d30c`. Источник: [release v2.3.1](https://github.com/GameTechDev/PresentMon/releases/tag/v2.3.1), [CLI/CSV](https://github.com/GameTechDev/PresentMon/blob/v2.3.1/README-ConsoleApplication.md), [ограничения OpenGL и ETW](https://github.com/GameTechDev/PresentMon/blob/v2.3.1/README.md).

Команды из корня, Node 24 и PowerShell 7:

```powershell
npm.cmd run setup:benchmark
npm.cmd run capture:benchmark -- -TargetProcessId 12345 -Variant space-hud-on -Repetition 1 -ConditionsFile .reports/benchmark/conditions.json
npm.cmd run analyze:benchmark -- .reports/benchmark/<run-directory> --out .reports/benchmark/diagnostic.json
```

`12345` заменить точным PID уже запущенного Minecraft, а не Gradle daemon. Сборщик принимает только java/javaw, отслеживает время создания процесса против повторного использования PID и прекращает запись при его выходе. Он не запускает игру и не принимает её JVM/auth-аргументы. Перед записью проверяет tool hash и чистоту исходников game. Начальные параметры — 30 секунд прогрева и 60 секунд измерения. Каждые 500 мс снимаются working set и private bytes только выбранного процесса; аппаратные условия содержат CPU/GPU/driver/RAM/OS build, без имени машины/пользователя и без command line.

Шаблон условий: [benchmark-conditions.example.json](benchmark-conditions.example.json). Два SHA в нём намеренно невалидны: их нужно заменить реальными значениями snapshot мира и `options.txt`. Сборщик валидирует JSON до старта. Условия записывает оператор по фактическому профилю/сцене; инструмент не доказывает положение камеры, наличие нужного мира или статус HUD автоматически. Вариант с HUD требует master ON и всех четырёх модулей ON, вариант без HUD — master OFF при той же раскладке. Options должны совпадать во всех вариантах.

Каждый запуск получает новый каталог `.reports/benchmark/<timestamp-variant-repetition-random>/` и собственное имя ETW session. Сохраняются `capture.json`, `frames.csv`, `memory.json`, stdout/stderr и, только после успешной валидации, `summary.json`. Не останавливаются чужие ETW sessions, не устанавливаются сервисы/драйверы, не запрашивается автоматическое повышение прав. Raw файлы игнорируются Git. Анализатор не перезаписывает существующий отчёт.

## Протокол полного сравнения

1. Подготовить отдельный мир/snapshot с фиксированными координатами, yaw/pitch, временем суток, погодой и mob spawning. Исходный snapshot восстановить перед каждым новым процессом. Исходные save-файлы и пользовательскую `.minecraft` не использовать. Зафиксировать способ получения hash snapshot.
2. Использовать 1280×720, GUI Normal, одинаковые JDK/heap, драйвер, графические настройки, resolution, resource packs и процессы в фоне. VSync выключить, FPS slider установить Unlimited; в 1.8.9 записать фактический `maxFps` из options, а не значение FPS на экране. Не менять системные настройки для серии.
3. Сначала провести фиксированную сцену без движения: 30 секунд прогрева, затем 60 секунд записи. Это статический baseline, не оценка всех PvP-сцен. Не открывать меню, F3, не переключать приложения и не сворачивать игру во время capture. Отдельную движущуюся сцену считать другой серией с другим sceneId.
4. Сделать девять независимых запусков: repetition 1 — vanilla → Space HUD OFF → Space HUD ON; repetition 2 — OFF → ON → vanilla; repetition 3 — ON → vanilla → OFF. Так уменьшается зависимость от порядка/прогрева машины. Каждый вариант получает повторы 1/2/3.
5. Vanilla должна быть явно зафиксированным контрольным запуском. Empty Fabric не называть чистой vanilla. Если vanilla требует другого JDK/loader/runtime, описать различие; итог не будет изолированной оценкой накладных расходов HUD. Официальный launch/runtime baseline остаётся частью незавершённой SC-10.
6. Передать девять каталогов анализатору одной командой. Он требует все варианты/повторы без дубликатов, одинаковые условия/hardware/tool/timing и одинаковый game source tree для шести Space-запусков. Серия короче 60 секунд или с прогревом меньше 30 секунд отклоняется. Один каталог даёт только диагностический отчёт с `completeFrameComparison=false`.

Сборщик FPS **не измеряет время запуска**: `startupMs=null`, `allStartupMeasurementsPresent=false`. Возраст Java-процесса не заменяет время до первого управляемого кадра мира. Новый отдельный [QA-сборщик startup](STARTUP-TIMING.md) не дописывает эту метрику в старые captures. Для полного SC-13 ещё нужен замер от spawn до одинаковой конечной точки готового кадра во всех вариантах и повторная проверка авторизованного пути после SC-10.

## Определения метрик

- Средний FPS = `1000 / mean(msBetweenPresents)` после исключения только самого первого интервала, который может начинаться до capture.
- 1% low = `1000 / mean(самые медленные ceil(N × 0.01) интервалы)`. Это выбранное явное определение, не FPS-перцентиль. P95/P99 frametime — nearest rank. Длинные stalls и dropped presents сохраняются. Малое число кадров выдаёт предупреждение; плохой FPS не отбрасывается ради красивого отчёта.
- Запись содержит один PID и одну swap chain. Не принимаются нулевые/нечисловые интервалы внутри серии, нестрогие timestamps, ошибки CSV, неполная длительность и пропуски покрытия времени. Сумма интервалов должна согласовываться с диапазоном timestamps в пределах max(50 мс, 2%).
- Working set включает общие физические страницы; private bytes — приватная committed memory процесса. Это разные показатели. `max` — максимум снятых samples, не гарантированный пик между опросами. Большие пробелы в memory sampling отклоняются.
- Итог серии — медианы трёх результатов каждого варианта и диапазон средних FPS; кадры разных запусков не склеиваются в один более тяжёлый прогон. Raw SHA-256 включаются в отчёт.

Present intervals не равны displayed FPS или input latency. OpenGL `Runtime=Other` имеет меньше instrumentation; эти ограничения PresentMon сохраняются в отчёте. Значение FPS на F3 и нынешние screenshot не используются как benchmark.

## Первый probe и совместимость 24 октября

Первый сборщик без elevation запущен против отдельного Java-процесса QA, диагностический интервал 5 секунд / warmup 0. PresentMon отказал: `failed to start trace session: access denied`. Сборщик сохранил `status=failed`, вернул exit 1; CSV/summary не созданы. Анализатор отдельно отказался принять эту запись. Это подтверждённое ограничение прав ETW, а не нулевой или измеренный FPS. Позже пользователь физически подтвердил UAC для ограниченного сборщика; успешные записи описаны ниже. Права/группы Windows, сервисы и системные настройки не менялись, игра оставалась обычным процессом.

13 тестов анализатора проходят на явно синтетических данных: точная арифметика/1% low/stall, слабая машина с малым числом кадров, quoting/BOM/CRLF, неправильный PID/несколько chains, повреждённые значения, длительность/покрытие/RAM, failed capture, повторные номера/расхождение условий и отказ перезаписи результата. Они автоматически входят в `npm test` и CI.

Дополнительная игровая совместимость выполнена на прежнем game tree `ad06bc5f13ca76788f6c0832e9f72e77843219ac`: render distance 4, Fast graphics, particles minimal, mipmap 0, Unicode font; собственный pack format 1 изменяет vanilla-строку на `QA Singleplayer`, что подтверждает загрузку. Это проверка минимального language pack вместе с Unicode-режимом, не проверка всех сторонних HD/font packs. Виджет FPS 3× виден у правого нижнего края, перетаскивается к левому нижнему краю и сохраняет 0/0 без обрезки. F1/F3 скрывают/возвращают HUD, Alt+Tab вызывает обычную паузу, после возврата CPS=0. Save and Quit → Quit Game завершились с кодом 0. Исходные QA options и HUD config восстановлены побайтно; обычный инстанс/сайт не менялись.

## Девять локальных captures — 24 октября 2026

[Полный отчёт: metadata, raw SHA-256, результаты и проверка сцены](qa/benchmark-static-2026-10-24.json). Для каждого запуска восстановлена отдельная копия одного snapshot, создан новый Java-процесс, выдержаны 30 секунд прогрева и 60 секунд записи. Все девять captures прошли проверки CSV/времени/памяти, все 27 raw hashes перепроверены. После штатного выхода NBT каждого мира содержит исходные XYZ `74.5 / 90 / -20.5` и rotation `180 / 15`; девять exitCode=0. Ни один probe со смещением камеры или прерванный инстанс в отчёт не включён.

Это медианы трёх отдельных результатов. Working set — медиана sampled median каждого запуска; max private — медиана sampled maximum, не гарантированный пик между опросами. Present FPS не означает displayed FPS: dropped presents сохранены, OpenGL `Runtime=Other` имеет сокращённую instrumentation.

Условия: i5-12400F, RTX 3060, driver `32.0.16.1088`, Windows build `26200`, Java Temurin `21.0.12.1+1`, Minecraft 1.8.9, heap 3072 МиБ, 1280×720, GUI Normal, Fast, distance 8, minimal particles, mipmap 0, VSync OFF, Unlimited (`maxFps=260`). Vanilla запускает `net.minecraft.client.main.Main` без Fabric/Space, но использует общие обновлённые закреплённые LWJGL/Log4j. Это локальный контроль, а не pristine official distribution или авторизованный baseline SC-10.

Snapshot hash: sorted relative paths с `/` и SHA-256 каждого файла, строки `path:hash`, объединённые `\n`, затем SHA-256 UTF-8 строки. Результат `9592056bf46f1ca1737d31d6d54a596d98d2dc04e87414cc0f3da5ebe919a5c4`. Исходный `options.txt`: `03ed3d088f51f3eb816d411bcb2912a6704c2aacd3731488073f648002fe270c`. DayTime=6000, погода ясная, mob spawning/daylight cycle/random ticks выключены, creative flight; существующие entities не удалялись. Между процессами snapshot восстанавливался, но мир во время каждого прогона продолжал симуляцию.

Автоматический ввод мыши смещал камеру в предварительных probes. Для статической серии только benchmark-инстансы получили `mouseSensitivity=-1/3`, что даёт практически нулевой коэффициент поворота в vanilla. После серии восстановлено `mouseSensitivity=0.5`; в последнем окне UI подтвердил 100%. Обычные игровые настройки пользователя не менялись. Сборщик и игра завершены.

После первых трёх captures пользователь приостановил серию. Остальные шесть выполнены позже в тот же день; в ранних window inventories присутствовал Steam, после возобновления — отсутствовал. Фоновая загрузка и тепловой режим не измерялись. Диапазоны FPS перекрываются: разность медиан не доказывает причинный эффект HUD. `completeFrameComparison=true` означает наличие девяти совместимых по схеме записей, а не полную приёмку SC-13 или доказанную контролируемость среды.

Game tree прежний: `ad06bc5f13ca76788f6c0832e9f72e77843219ac`, JAR SHA `11299c35e8812de73373f75c0a3cef721f40308bb7f510fa7387c4f70c376257`, исходники/сборщик capture commit `f1dcc2973e2df2b7ce63c655b242aec59a458120`. Raw/runtime остаются игнорируемыми. Отдельный локальный архив содержит девять CSV/память/metadata/summaries и manifest 27 raw hashes.

SC-13 остаётся открытой: startupMs=null, нужны точный startup timing с одинаковым готовым кадром, непрерывное контролируемое сравнение и официальный runtime/совместимость после SC-10. Последующий [локальный startup-срез](STARTUP-TIMING.md) даёт только честные верхние границы до меню Space, а не полный benchmark. Этот раздел завершает локальный сбор девяти captures; оптимизаций и обещаний FPS не добавлено.
