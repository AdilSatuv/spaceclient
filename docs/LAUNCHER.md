# Space Launcher — первый desktop-каркас

Windows x64 development-лаунчер: профили, Java, подготовка/откат файлов Minecraft и собственного JAR, локальный ник и запуск одиночной игры — [SC-25](LOCAL-LAUNCH.md). С 3 ноября добавлены Space-регистрация/вход, ник/скин/плащ общего аккаунта, явное применение внешности, backup/restore настроек и экспорт безопасной диагностики. Development setup существует; Microsoft-вход и подписанный публичный релиз остаются отдельными задачами.

## Стек и границы

Electron **45.0.0**, React/ReactDOM **19.3.1**, TypeScript **5.9.3**, esbuild **0.28.2**, Node.js разработки **24+**. Версии закреплены package-lock.json. Electron выбран для первого Windows-прототипа как предусмотренный SPEC кандидат; переход к установщику потребует отдельной оценки размера, RAM и подписания. Версии Electron сверены с npm и [официальным списком релизов](https://releases.electronjs.org/release); это не обещание бессрочной актуальности.

Начальный локальный срез стоимости: распакованный `node_modules/electron/dist` занимает 374 097 589 байт (~357 МиБ). Сумма WorkingSet64 процессов с точным путём этого electron.exe составила 376 340 480 байт (~359 МиБ). Working set может учитывать общие страницы несколько раз; это одиночный снимок, без подтверждённой UI-приёмки, а не private RAM, размер установщика или сравнительный benchmark.

- `src/main/index.ts`: сборка зависимостей и lifecycle; `main/application`: команды и порты без Node/Electron; `main/electron`: окно, native dialog, shell, протокол и IPC. Остальные модули main владеют настройками на диске, Java, подготовкой и проверкой файлов.
- `src/preload.ts`: 26 конкретных typed-функций через contextBridge; ipcRenderer/send/execute/fs наружу не передаются. Installation-функции принимают только ID существующего профиля: get/start/cancel; progress опрашивается с интервалом 650 мс, прямых IPC event streams наружу нет.
- `src/shared/ipc.ts`: единая типизированная карта команд; `models.ts` и `installation.ts`: данные. `contracts.ts` — совместимый экспорт типов; неизвестные значения повторно валидируются в main.
- `src/renderer/`: React и CSS, локальные ресурсы; нет Node.js и сетевых запросов. `model/LauncherSession` владеет черновиком и состоянием команд; hooks подключают модель/API, pages отображают экраны. Только `index.tsx` получает window.space.
- `scripts/build.mjs`: отдельные main/preload CJS bundles и статический renderer. Нет dev-server с ослабленной CSP.

Подробная схема, правила импортов и дальнейшего расширения — [ARCHITECTURE.md](ARCHITECTURE.md). Автотесты проверяют границы зависимостей и отсутствие runtime-циклов; неизвестные исключения заменяются безопасным сообщением на границе dispatcher и асинхронного статуса установки.

Следуем [официальным рекомендациям Electron](https://www.electronjs.org/docs/latest/tutorial/security): sandbox/contextIsolation=true, nodeIntegration=false, webSecurity=true. Renderer загружается через `space://app/index.html`; протокол отдаёт только четыре известных ресурса. CSP запрещает inline/eval, сеть, frames, формы и объекты. Все IPC проверяют точные webContents, mainFrame и URL. Окна, навигация, webview и browser permissions запрещены. Это реализованные ограничения и модельные тесты, а не независимый аудит или завершённое runtime-испытание всех обходов.

## Настройки и поведение

`settings.json` schemaVersion=2 (v1 мигрирует без потери профилей): локальный ник или null, список до 10 профилей, активный ID, имя, memoryMb, путь к java.exe. Нет токенов, паролей и произвольных launch arguments. Записи последовательно проходят очередь и временный файл с rename; изменение памяти применяется после успешной записи, временный файл очищается при ошибке. Перед чтением проверяется размер: свыше 64 КиБ файл восстанавливается как повреждённый без JSON parse. При неподдерживаемом или повреждённом JSON сначала создаётся `settings.invalid-<time>-<uuid>.json`, оригинал остаётся до следующего сохранения. Если резервная копия невозможна, исходный файл не перезаписывается.

Память: минимум 1024 МБ, шаг 256 МБ, максимум — меньшее из 16384 МБ и аппаратного лимита с резервом 2048 МБ системе; нижняя граница аппаратного лимита 1024 МБ. Это ограничение настроек, а не доказательство пригодности маломощного устройства для игры. По умолчанию 2048 МБ либо доступный лимит. Профиль получает отдельный `instances/<id>`; ID не допускает traversal, существующая ссылка/junction каталога отклоняется.

Для текущего прототипа выбран уже проверенный dev-runtime **Java 21 x64**. Это временная политика до установочного манифеста игры. Выбор java.exe выполняется native picker; renderer не задаёт путь для запуска. Допускается абсолютный путь на локальном Windows-диске; UNC, включая вариант с прямыми слешами, и device paths отвергаются. Проверка делает только `-XshowSettings:properties -version` через execFile, shell=false, timeout 5 с, output limit 64 КиБ. JVM options из JAVA_TOOL_OPTIONS/_JAVA_OPTIONS/JDK_JAVA_OPTIONS/CLASSPATH не наследуются. В UI возвращаются разобранные major/bits и краткое сообщение; raw output не показывается. Проверки Java и native picker не запускаются параллельно сами с собой. Java-проверка профиля и runtime preflight получают собственные сигналы отмены: закрытие лаунчера отменяет диагностические процессы и ожидает их `close`. Уже работающая игра этим не завершается. После начала shutdown новые команды проверки Java отклоняются; ранняя отмена не начинает stat/spawn. Подробнее — [JAVA-PROBE-HANDOFF-2026-11-02.md](JAVA-PROBE-HANDOFF-2026-11-02.md).

Интерфейс переработан на локальных компонентах **shadcn/ui**: стиль сайта Eclipse: почти чёрный звёздный фон, медно-янтарный акцент, Ringworld, Lucide и компактная сцена планеты. Обзор, профили и настройки используют общую систему Card/Button/Input/Badge. Форма сохраняет черновик при переключении раздела; смена профиля до save/cancel блокируется. Локальный запуск отделён от будущего официального онлайн-входа; ник не является зарегистрированным аккаунтом. Состав компонентов, лицензии, статический Tailwind build и проверка трёх экранов на четырёх размерах — [LAUNCHER-DESIGN.md](LAUNCHER-DESIGN.md).

## Аккаунт Space и внешность

Вкладка «Аккаунт» использует тот же Nest Account API, что и `/account` сайта. По умолчанию origin `http://127.0.0.1:3001`; `SPACE_ACCOUNT_API_URL` задаётся только процессу main (HTTPS либо loopback). Для preview со случайным портом нужно передать `apiUrl` из `.reports/local-preview.json`. Сессия привязана к origin и хранится OS-encrypted отдельно от settings.json; пароль не сохраняется. Гостевая локальная игра доступна без входа.

Чтобы перезапуск preview сохранял origin сессии, задайте постоянные `SPACE_PREVIEW_API_PORT` и `SPACE_PREVIEW_PORT` перед `npm run preview:web`. Значения0/пусто выбирают свободные порты автоматически; фиксированные значения должны различаться и оставаться в0–65535. Bind всегда loopback. Не запускайте вторую копию поверх уже работающих портов.

Регистрация/вход не меняют сохранённый локальный ник. После редактирования профиля нажмите «Применить» перед следующим запуском: новый ник может изменить offline identity. Только публичные поля и проверенные PNG попадают в instance. В Minecraft отдельный раздел «Косметика» управляет крыльями, нимбом, палитрой/размером и видимостью Space-текстур. Пока эта внешность локальная для Space, без изменения официального Mojang-профиля.

Backup/restore находится в настройках и действует на текущий профиль. В копию входят options и Space HUD/mod/browser/waypoint/cosmetic preferences; миры, аккаунты и Java не включаются. Во время запущенной игры обслуживание блокируется. Диагностика экспортируется через native save picker и не содержит ников, токенов, путей или сырых логов. Подробные границы — [контракт аккаунта](ACCOUNT-AND-COSMETICS-CONTRACT.md).

## Запуск из исходников

Из корня репозитория:

```powershell
npm.cmd ci
npm.cmd run launcher
```

Electron при первом запуске загружает свой официальный runtime, если binary ещё отсутствует. Скрипт `launcher` сначала собирает исходники. Повторный запуск готовой сборки: `npm.cmd run start --workspace @space/launcher`.

Обычный каталог данных определяется Electron userData для имени Space Client. Для изолированного dev-теста:

```powershell
$env:SPACE_LAUNCHER_DATA = Join-Path (Get-Location) '.reports/launcher-desktop'
npm.cmd run launcher
```

Этот override действует только в unpackaged-приложении. Не использовать личную `.minecraft` для тестов. Не коммитить dist, Electron runtime, .reports и локальные профили.

- Build main/preload/renderer и TypeScript проходят.

- Настоящий `inspectJava` с локальным `.tools/jdk-21/bin/java.exe` вернул usable=true, major=21, bits=64.
- После явного разрешения пользователя осмотр возобновлён. Через окно проверены три раздела, независимые профили/RAM/Java, native picker, реальная Java 21 x64, сохранение и выбор после перезапуска, защита черновика активной карточки, Tab/focus/стрелка RAM/отмена. Подробности и ограничения — [LAUNCHER-QA.md](LAUNCHER-QA.md).
- Таймаут/переполнение вывода реального Java-процесса, внешний frame/навигация в живом окне, полный keyboard-only маршрут, zoom и reduced-motion ещё требуют runtime-проверки.

Установка: downloader/pins/cache/cancel/resume, очередь, resolver 1.8.9, Log4j 2.26.1, [loader/LWJGL manifest](LOADER-MANIFEST.md), natives и [собственный game bundle](GAME-BUNDLE.md). Добавлены [хранилище будущей Microsoft-сессии и callback](AUTH.md) с MSAL 7.1.1 и асинхронным Windows DPAPI; **106 launcher tests** проходят после локального launch-среза (см. LOCAL-LAUNCH.md).
