## Lighthouse: три прогона каждой страницы

Lighthouse 13.5.0, Headless Chrome 155, production Next.js на loopback с настоящим NestJS API; mobile 412×823, DPR 1.75, simulated throttling 150 ms RTT / 1638.4 Kbps / CPU ×4. Отдельные новые профили Chrome, без пользовательской сессии. Установлен локальный devDependency, версия закреплена. [Числовые результаты всех 15 прогонов и условия](qa/lighthouse-2026-10-23.json); исходные полные отчёты остаются в игнорируемом `.reports/lighthouse/`.

Первый аудит обнаружил низкий контраст footer wordmark (1.39:1): новый цвет даёт 4.12:1 на фоне подвала и проходит аудит. HUD-иллюстрация переведена с quality 80 на 75. На features/download/updates первоначальный CLS достигал 0.25/0.20/0.11 из-за поздней смены серверного shell; метаописание также попадало вне head. Streaming metadata отключена для всех посетителей через `htmlLimitedBots: /.*/`: общий с Page API-запрос завершается перед выдачей metadata. Компромисс — первый ответ ждёт этот ограниченный timeout запрос. Повторные 15 прогонов подтверждают CLS 0; title/description в head дополнительно проверяет маршрутный smoke-script.

SEO >=95 пока **не пройдено**: preview намеренно имеет noindex и robots disallow. Во всех повторных отчётах остальные оцениваемые SEO-аудиты проходят. Не снимать запрет индексации ради оценки; повторить на настоящем HTTPS-origin после размещения. Результаты локального лабораторного профиля не заменяют полевые Core Web Vitals и ручную доступность.

Повторение после build и запуска обоих процессов:

```powershell
npm.cmd run audit:web -- / /features /download /updates /help
```

`SPACE_LAB_RUNS` задаёт 1–5 прогонов (по умолчанию 3), `SPACE_LAB_OUTPUT` — папку отчётов, `SPACE_WEB_URL` — тестируемый origin. Требуется установленный Chrome; можно передать `CHROME_PATH`. Инструмент использует [официальный Lighthouse CLI](https://github.com/GoogleChrome/lighthouse#using-the-node-cli). Схема фокуса меню сверена с [WAI Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/); база UI/UX Pro Max дала рекомендации по видимому focus, но отдельного точного результата по focus trap не нашла.

## Ещё проверить

- Полный keyboard-проход всех страниц и focus trap/видимость фокуса на всех размерах; уже проверенные Escape/return-focus не заменяют весь проход.
- Сверить фактическое содержимое системного clipboard в обычном пользовательском браузере; уже проверены UI feedback и ручное выделение.
- 200% zoom, reflow и reduced-motion в браузере; media rule в CSS сама по себе не подтверждает приёмку.
- Повторить SEO/performance на production HTTPS-origin; локальные три измерения выполнены и записаны выше.
- Финальная библиотека tokens/components/control states в Figma; подтвердить облачную синхронизацию мобильного фона. Созданные шесть макетов не означают завершение SC-17.
