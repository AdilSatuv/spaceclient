Повторение после build и запуска обоих процессов:

```powershell
npm.cmd run audit:web -- / /features /download /updates /help
```

`SPACE_LAB_RUNS` задаёт 1–5 прогонов (по умолчанию 3), `SPACE_LAB_OUTPUT` — папку отчётов, `SPACE_WEB_URL` — тестируемый origin. Требуется установленный Chrome; можно передать `CHROME_PATH`. Инструмент использует [официальный Lighthouse CLI](https://github.com/GoogleChrome/lighthouse#using-the-node-cli). Схема фокуса меню сверена с [WAI Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/); база UI/UX Pro Max дала рекомендации по видимому focus, но отдельного точного результата по focus trap не нашла.

## Новый срез Nebula: цвет и движение

После запроса пользователя обновлены палитра, CTA, градиент заголовка, звёзды, две орбиты, метеор, мягкое движение desktop-сцены, hover и reveal секций. Нет новой animation-зависимости: CSS + IntersectionObserver/Web Animations. Текст остаётся доступным без JavaScript; начальный HTML не скрывает секции. Reveal использует transform/opacity и срабатывает один раз для элемента, observer/animations очищаются при смене страницы и предпочтений. Пауза управляет CSS-анимациями и отменяет текущие reveal; настройки системы имеют приоритет. Кнопка находится в шапке и не перекрывает hero.

- Пауза → computed animation-play-state=paused, aria-pressed=true; возобновление → running. На mobile отключён дрейф картинки; кнопка управления 44×44 px.

## Продолжение: сохранение настроек и навигация

Пауза анимаций сохраняется локально под ключом `space.motion`, без отправки на сервер. До чтения предпочтения после hydration декорация остаётся на паузе; контент виден в серверном HTML. Системный reduced-motion сохраняет приоритет. Ошибки доступа к localStorage обработаны: переключатель продолжает работать в текущем посещении; отдельная browser-проверка заблокированного storage пока не выполнена.

- На production-сборке проверены пауза → reload → `data-motion=paused` / `animation-play-state=paused`, затем возобновление → reload → `active` / `running`.
- Меню открыто при 390 px: фон заблокирован. После расширения до 1024 px dialog закрыт, `aria-expanded=false`, body overflow восстановлен, фокус на видимой ссылке логотипа. Смена маршрута также закрывает dialog; восстановление прежнего inline overflow и cleanup реализованы эффектом.
- Полный Tab-проход пяти основных страниц на 390×900 и 1440×900: 15–27 доступных элементов на страницу, каждый проверенный элемент находится в viewport и имеет outline solid 2 px. На помощи закрытые details не включались в число доступных ссылок; после Enter на FAQ ссылка внутри доступна по Tab. Это локальная проверка двух размеров, а не заключение о всех сочетаниях браузеров и assistive technology.
- Общая кнопка повторного запроса теперь показывает «Повторяем запрос…» и `aria-busy` во время ожидания; она используется и вне каталога загрузок.
- TypeScript, production build, 11 unit/HTTP tests, state fixtures, route/head/404 smoke и форматирование проходят.

Попытка проверить настоящий 200% zoom в настольном Chrome остановлена инструментом Computer Use: он не смог надёжно определить URL текущей вкладки. Ввод в приложение прекращён; масштабирование не считается проверенным. Предыдущие responsive и Lighthouse результаты выше относятся к указанным там срезам и не заменены новыми измерениями.

## Пользовательские сценарии — 24 октября 2026

Приёмка WEB-03/04/06/07/09/10 дополнена настоящими действиями в Chrome на production-сборке. Найдены и исправлены два несоответствия: поиск помощи игнорировал FAQ, а Back мог показывать несохранённый следующий запрос/канал поверх результатов предыдущего URL. FAQ теперь участвует в поиске, пустой результат содержит ссылку на обращение, а общая FilterForm восстанавливает серверные default values после восстановления истории.

- Полный прогон: **42** сочетания маршрутов/ширины, **6** проверок zoom/motion/menu/clipboard, **20** дополнительных сценариев. [Отчёт](qa/website-user-flows-2026-10-24.json).
- На 390/1440 px: поиск/категория/статус и reload/Back/reset возможностей; смена канала загрузок и Back; 14 fixture-новостей с пагинацией 12+2, статья, Back и сброс страницы при смене типа; поиск FAQ/инструкций без учёта регистра, пустой результат, ссылки и независимое открытие FAQ клавиатурой.
- Skip link, Tab/Shift+Tab в меню, видимый focus, Escape, переход и расширение до desktop освобождают scroll. Unknown route/help/update сохраняют настоящий HTTP 404.
- HTTP 503, invalid JSON и timeout воспроизведены отдельно для features/download/updates. Все девять случаев показывают ошибку вместо ложного empty. Нажатие retry включает busy/disabled, повторно запрашивает API и восстанавливает содержимое; DOM-маркер подтверждает отсутствие перезагрузки документа.
- Внедрённый localStorage SecurityError на чтении и записи не мешает паузе/возобновлению; это тест fallback, а не изменение настроек браузера/ОС. Viewport-снимки помощи осмотрены; reduced-motion включён только в тестовой вкладке. Full-page capture не используется для этих снимков: изменение viewport в Chrome может показать скрытый fixed skip-link, хотя в настоящем viewport его rect.top=-100.
- Окончательный /help с новой формой: три sequential mobile Lighthouse 13.5.0 прогона, медиана Performance **99**, Accessibility **100**, SEO **63** (preview noindex), LCP **1966 мс**, CLS **0**. Условия и source hashes: [отчёт](qa/website-help-search-lighthouse-2026-10-24.json). Остальные страницы в этом срезе повторно не измерялись.
- Сборка Next, 120 unit/HTTP tests, TypeScript, state fixtures и форматирование прошли. CI сохраняет только отчёты и PNG из собственного browser run, исключая каталог профиля. [Матрица приёмки](WEB-ACCEPTANCE.md) разделяет выполненные local-проверки и оставшиеся production-условия.
